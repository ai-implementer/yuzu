# 執筆の基本

## ページとナビゲーション

`content/**/*.md` の 1 ファイルが 1 ページになり、**ディレクトリ階層が
そのままサイドバーの階層**になります。`guide/writing.md` は
`/guide/writing/` として配信されます。

- 並び順は frontmatter の `order` 昇順（未指定はファイル名順で最後尾）
- ディレクトリの表示名・並び順・リンク先は、その配下の `index.md` から取ります
- h2 / h3 見出しは右側の「目次」に自動で載ります（範囲は `theme.toc.levels` で変更できます。h3 以降は入れ子で表示されます）
- 全ページはサイドバーの表示順で連結され、ページ末尾に**前後ページリンク**、
  ページ上部に**階層パンくず**が付きます

> [!WARNING]
> `guide.md` と `guide/index.md` はどちらも `/guide/` になります。両方あると
> 同じファイルへ書き込むことになるため、ビルドが `route-conflict` で止まります。
> どちらか一方にしてください。

ファイル名はそのまま URL になります（小文字化や記号の置き換えはしません）。
`#` `?` `%` `"` のような URL で意味を持つ文字を含めるとリンクが壊れるため、
`unsafe-page-path` でビルドが止まります（`a#b.md` の URL `/a#b/` は
ブラウザから `/a` ＋ フラグメント `b/` に見えます）。

## frontmatter

各ページの先頭に YAML frontmatter を書けます。使えるキーは次の 7 つです
（未知のキーは `yuzu lint` が警告します）:

```yaml
---
title: ページタイトル # ナビの表示名（未指定は h1 → ファイル名）
order: 1 # ナビの並び順（未指定はファイル名順で最後尾）
draft: true # ビルドから除外する
description: 説明 # meta description
llms: false # llms.txt / llms-full.txt から除外する
aliases: ["guide/old-name/"] # 旧 URL（リダイレクトを生成）
lintDisable: ["term-variant"] # このページに限り lint ルールを抑制
---
```

### 下書き（draft）

`draft: true` のページは通常ビルドから除外されます。書きかけの確認には
`yuzu dev --drafts` / `yuzu build --drafts` を使うと、**下書きバナー付き**で
プレビューできます（通常ビルドに戻すと下書きの出力は自動で掃除されます）。

### ページの移動とリダイレクト（aliases）

ページを移動・改名したら、旧 URL を `aliases` に残します。ビルド時に
旧 URL へ**リダイレクト HTML**（meta refresh + canonical + JS フォールバック）が
生成され、外部からのブックマーク・リンクが切れません:

```yaml
---
title: 品質チェック
aliases: ["guide/lint/"] # 以前この URL だった
---
```

- パスはサイト内の route 形式で書きます（先頭 `/` と末尾スラッシュの省略は可）。
  `base_url` 設定にも自動で追随します
- エイリアスが実ページや他のエイリアスと衝突すると、ビルドは中断し
  `yuzu check` がエラーとして報告します
- エイリアスを外すと、旧リダイレクトは次のビルドで自動掃除されます
- リダイレクトページは検索インデックス・llms.txt に載りません。また
  **本文からエイリアス URL へリンクすると `yuzu check` がリンク切れとして
  指摘します**（サイト内のリンクは常に移動後の URL へ張る運用です）

## GFM 記法

GitHub Flavored Markdown の表・タスクリスト・打ち消し線・autolink が使えます。

| 記法 | 例 |
| --- | --- |
| 表 | この表がそれです |
| タスクリスト | 下の例 |
| 打ち消し線 | ~~古い記述~~ |
| autolink | <https://github.com/ai-implementer/yuzu> |

- [x] 構成を決める
- [ ] 本文を書く

日本語の括弧・句読点に隣接した強調も効きます。素の CommonMark では約物に隣接すると
強調が閉じられず `**` がそのまま表示されてしまうため、書き手が語順を変えて
回避する必要がありました。この行がその例です — これは**「重要」**です。
**この文は重要です。**但し例外もあります。

## Admonition

GitHub 互換の `> [!NOTE]` 形式で注意書きが書けます（5 種類）。

> [!NOTE]
> 補足情報。ラベルは既定で英語です。

> [!TIP]
> 知っていると便利な使い方のヒント。

> [!IMPORTANT]
> 目的を達成するために必ず知っておくべきこと。

> [!WARNING]
> 問題を避けるために注意が必要な内容。

> [!CAUTION] 破壊的操作に注意
> `> [!CAUTION] タイトル` のように 1 行目へ書くと、ラベルを日本語などへ
> 上書きできます。

### 折りたたみ

種別の直後に `-` / `+` を付けると、折りたたみ（`<details>`）になります
（Obsidian と同じ記法。ネイティブ要素なのでクライアント JS は不要です）:

- `> [!NOTE]- タイトル` — **閉じた状態**で表示（クリックで開く）
- `> [!NOTE]+ タイトル` — **開いた状態**で表示（クリックで閉じられる）

> [!TIP]- 長い補足はここに畳んでおけます
> 折りたたみの中身も検索インデックス・llms.txt に収録されます
> （閉じていても内容は HTML に含まれるため）。
> 
> - リストやコードなど、通常の本文がそのまま書けます
> - タイトルを省略（`> [!TIP]-` だけ）にすると既定ラベルになります

検索結果や図表の参照から折りたたみの**中**へジャンプしたときは、該当箇所が
見えるように自動で開きます（JS 無効時は閉じたままですが、クリックで開けます）。

## 脚注

本文に脚注参照を書けます[^sample]。表示では定義がページ末尾に集約され、
相互リンクされます。

[^sample]:
    脚注の本文。`yuzu fmt` は定義をこの位置のまま温存し、未参照の定義も
    消しません。

## 画像と添付ファイル

置き場所は 2 通りあります:

1. **`public/` に置く** — そのまま `dist/` へコピーされ、`/images/...` の
   サイト絶対パスで参照します（サイト共通のロゴなど向け）
2. **ページと同じディレクトリに置く** — `![図](diagram.png)` のように
   相対パスで参照します。content 配下の `.md` 以外のファイルは `dist/` へ
   自動コピーされ、リンクは正しい URL に解決されます（ページ専用の図向け）

![yuzu ロゴ](/images/yuzu-logo.svg)

参照切れはどちらの方式でも `yuzu check` が検出します。

## Markdown 断片のインクルード

共通の注意書き・用語の説明・免責文が複数ページに散ると、片方だけ古くなる事故が
起きます。言語を `include` にしたフェンスで、**Markdown 断片を本文へ展開**できます:

````markdown
```include file="snippets/draft-note.md"
```
````

```include file="snippets/draft-note.md"
```

- 断片はプロジェクトルート相対で参照します（`content/` の外に置けます。
  慣例は `snippets/`。`content/` 内に置くとそれ自体がページになるので、
  避けるか `input.ignore` で除外してください）
- 展開された内容は通常の本文と同じに扱われます: リンクの解決・コードの
  ハイライト・注記の描画・**検索の索引**（`search.index_code` と無関係）
- **断片は散文専用**です。見出し・図表キャプション行・脚注・frontmatter・
  `file=` 付きフェンス（インクルードの入れ子）は `yuzu check` が
  `include-error` で報告します
- 断片を編集すると、参照している全ページが次のビルドで更新されます
  （`yuzu dev` はプロジェクトルート全体を監視しているので保存だけで反映）

> [!NOTE]
> 制限: 断片内のリンクは `yuzu check` のリンク検査の対象外です（相対リンクは
> 取り込み先ページ基準で解決されるため、サイトルート相対で書くのが安全です）。
> llms-full.txt はフェンス原文のまま・断片自体は `yuzu fmt` の整形対象外です。

## 図表番号と相互参照

図・表・コードの直前または直後に**キャプション行**を書くと、ページ内で
自動採番されたキャプションになり、本文から参照できます:

````markdown
```mermaid
graph TD; A-->B
```

Figure: 依存関係の図 {#fig:deps}

詳しくは [](#fig:deps) を参照してください。
````

- 接頭辞は `Figure:` / `Table:` / `Listing:`（日本語の `図:` / `表:` /
  `リスト:` も使えます）。表示は「図 1」「表 1」「リスト 1」です
- 採番は**ページ内の連番**で、種別ごとに独立して数えます。
  設定 `markdown.crossref.numbering: "site"` にすると、サイドバーの表示順で
  **サイト全体の通し番号**になります
- `{#fig:deps}` がラベル（アンカー）です。省略しても採番・表示はされますが、
  参照はできません
- 参照は `[](#fig:deps)` のように**リンクテキストを空**にすると「図 1」が
  自動で入ります。`[この図](#fig:deps)` のようにテキストを書けばそのままです
- 存在しないラベルへの参照は `yuzu check` がリンク切れとして報告し、
  ラベルの重複は `yuzu lint` が警告します

キャプション行はただの段落なので、素の Markdown ビューアで開いても壊れません。
`yuzu fmt` を通してもラベルは書いたままの形（`{#fig:deps}`）で温存されます。

## 用語集と略語

設計書は略語が多く、初出の説明を毎ページ書くか読み手の記憶に頼ることになりがちです。
`yuzu.toml` に**辞書だけ**を置くと、本文の Markdown を 1 バイトも変えずに、
各ページの初出が `<abbr title="説明">` になり、**用語集ページが自動生成**されます:

```toml
[markdown.glossary.terms]
SSR = "Server-Side Rendering。ビルド時にサーバ側で HTML を組み立てること"
TOC = "Table of Contents。ページ内の目次"
```

原稿は普通に「SSR」と書くだけです（記法はありません）。素の Markdown ビューアで
開いても何も足されていないので、当然そのまま読めます。

- **置換はページ内の初出だけ**です。同じ用語が 20 回出ても点線の下線が付くのは
  最初の 1 回で、設計書の「初出で説明、あとは素のテキスト」という慣例に合わせています
- **見出し・リンクの文字列・画像の `alt`・インラインコード・数式・
  図表キャプションは対象外**です。見出しやリンクで初出を使い切らないので、
  本文の説明が確実に出ます
- **単語境界**は用語の端が英数字のときだけ見ます。`API` は `RAPID` や `APIs` には
  一致せず、日本語の用語（`分かち書き` など）は文中のどこでも一致します。
  用語が重なるとき（`API` と `API キー`）は**長いほうが優先**されます
- 説明文は `title` 属性に入るので、Markdown 記法ではなく素のテキストで書きます

### 自動生成される用語集ページ

`markdown.glossary.page`（既定 `"glossary"`）の URL に、用語ごとの見出しを持つ
ページが作られ、サイドバーにも載ります。普通のページとして扱われるので、
**検索・`llms.txt`・sitemap・パンくず**にもそのまま乗ります
（説明文で検索して用語集の該当項目へ飛べます）。

用語ごとに見出しがあるため、本文から `[SSR の説明](../glossary.md#ssr)` のように
アンカー付きでリンクでき、`yuzu check` のリンク検査も通ります。

- `page = ""` にするとページを作らず、`<abbr>` 化だけを使えます
- `"abbr": false` にすると逆に、本文は書いたままでページだけを作れます
- `page = "reference/glossary"` のように書けば、サイドバーの該当セクション配下に
  入ります
- ページは設定から作られるので `yuzu fmt` / `yuzu lint` の対象外です。
  実ページと URL が衝突したときは `yuzu check` が `route-conflict` で報告します

## 定義リスト

用語の段落 → 空行 → コロン（`:`）で始まる段落を書くと定義リスト（`<dl>`）になります:

```markdown
SSG

: Markdown などの原稿から静的な HTML サイトを生成する仕組み。

SSR

: ここではビルド時に図を SVG へ変換すること。
```

素の Markdown ビューアではコロンで始まる段落が並ぶだけなので壊れません。
`yuzu fmt` を通しても同じ形のまま温存されます。上の例はこう描画されます:

SSG

: Markdown などの原稿から静的な HTML サイトを生成する仕組み。

SSR

: ここではビルド時に図を SVG へ変換すること。

> [!NOTE]
> 用語をまとめて見せたいだけなら[用語集](#用語集と略語)の自動生成が使えます。
> 定義リストは**本文の流れの中で**用語を説明したいときに向きます
> （`<dt>` には id が振られないので、用語へのアンカーリンクは作れません）。

## その他の記法

引用・キーボード表記・区切り線にもテーマのスタイルが当たります。

> 引用ブロック。出典の明示や補足に使います。

検索ボックスへは <kbd>/</kbd> または <kbd>Cmd</kbd>+<kbd>K</kbd> で
フォーカスできます。
