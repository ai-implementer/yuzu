# 全文検索

ヘッダーの検索ボックス（<kbd>/</kbd> または <kbd>Ctrl/Cmd+K</kbd> で
フォーカス）から日本語で検索できます。文を単語に区切る日本語の分かち書きに対応し、
関連の深い順に結果を並べます。検索用のファイルは `dist/_search/` に出力される
静的ファイルです（仕組みは開発者向けの[検索の内部設計](../development/internals-search.md)）。
**サーバは不要**で、CDN や GitHub Pages のような静的ホスティングだけで
動きます。

検索ボックスは上位数件の**サジェスト**を出します。全件を見る・絞り込む・
結果を共有するのは、末尾の「**すべての結果を見る**」から開く
[検索結果ページ](#検索結果ページ)の役割です。

## セクション単位のヒット

検索は**セクション（h2 / h3）単位**です。結果は「ページ › 見出し」の形で並び、
選ぶと `#アンカー` へ直接ジャンプします。抜粋はクエリ一致箇所の周辺を
動的に生成し、分かち書き単位でハイライトします。

## 結果の並び順

結果は、語がどれだけ濃く出てくるか（BM25）で並びます。そのうえで、
**ページタイトルや見出しにクエリの語が入っている節を優遇します**。たとえば
このサイトで「設定」と検索すると、本文の長い設定のページ（タイトル
「設定（yuzu.toml）」）が先頭に来ます。

## 検索から外す

検索の結果に出したくないページは、frontmatter に `search: false` と書きます。
そのページの節はすべて索引から外れます（ナビ・sitemap・llms.txt には載ります）。
節ごとには外せません。

```yaml
---
title: 社内メモ
search: false
---
```

## 検索結果ページ

`search.page` を設定すると（このサイトでは `/search/`）、検索結果の
専用ページが生成されます。検索ボックスと違い、**状態がすべて URL に入る**のが
要点です:

- `?q=` がクエリ、`?section=` が絞り込みです。**URL を共有すれば相手にも
  同じ結果が再現**されます（例: [`/search/?q=検索`](/search/?q=検索)）
- 一度に出る件数は `search.page_size`（既定 10）で、残りは「さらに表示」で
  今の結果に**追記**されます
- 結果が複数のセクション（サイドバーの第 1 階層）にまたがるときは
  **区分のチップ**が出て、押すとそのセクションだけに絞り込めます。
  件数は**絞り込む前**の数（押す前に何件あるかが分かる）で、絞り込みは
  エンジン側で行うので表示件数も追加読み込みも正確です。
  区分が 1 つしか無いサイトではチップを出しません

検索結果ページは**既定では生成されません**（`search.page` の既定は空）。
既存プロジェクトの `content/search.md` と URL が衝突してビルドが
止まらないための既定で、`yuzu new` の雛形では有効になっています。
自動生成ページなのでサイドバー・検索インデックス・`llms.txt`・sitemap には
載りません。JavaScript が無効の環境では案内文だけが表示されます。

ターミナルからは `--section` で同じ絞り込みができます:

```bash
yuzu search --section ガイド "検索"
```

## タイポトレランス

1 文字の誤字（編集距離 1）に寛容です。たとえば「ダーくモード」で検索しても
「ダークモード」がヒットします。

## フレーズ検索

`"..."` で囲むと**フレーズ検索**になり、囲んだ語句が連続で出現する
セクションだけに絞り込めます（例: `"ライブリロード"`）。

- 引用部は誤字補正・同義語展開の対象外の**完全一致**です
- 全角引用符・カーリー引用符でも囲めます。閉じ忘れは末尾までが引用部です
- 抜粋ではフレーズ全体が 1 まとまりでハイライトされます

引用符なしの複数語クエリにも**近接ブースト**が働き、語がクエリ順に隣接して
出現するページが上位に来ます（ヒット集合は変わらず、順位だけが変わります）。

## 同義語とゆれ表記の展開

`lint.terms` の用語辞書と `search.synonyms` の同義語グループは、検索の
**クエリ拡張**に使われます。ゆれ表記で検索しても正表記のページがヒットし、
ハイライトも正表記側に付きます。グループの語はまとめて 1 語として数えるので、
両方の表記を書いた節だけが上位を占めることはありません。

このサイトの設定は次のとおりです。試しに `サーバー`（長音符あり）や
`ダイアグラム` で検索すると、`サーバ` や `図` と書かれたページが
ヒットします:

```toml
[lint.terms]
"サーバ" = ["サーバー"]
"ユーザ" = ["ユーザー"]

[search]
synonyms = [["図", "ダイアグラム"], ["設定", "コンフィグ"]]
```

## コードブロックの検索（`index_code`）

`search.index_code = true` にすると**フェンスコードブロックの中身も検索対象**に
なり、関数名や設定キーで設計書を引けます（既定は off）。このサイトでは
有効にしているので、たとえば `max_terms_per_shard` のような設定キーでも
このドキュメントを検索できます。

mermaid / openapi / jsonschema / math のような特別レンダリングされる
ブロックのソースは対象外です。

## ターミナルから検索する

`yuzu search` は**ブラウザとまったく同じエンジン**（同じ単語の区切り方と
インデックス）で検索します:

```bash
yuzu search "検索したい言葉"
yuzu search '"ライブリロード"'   # フレーズ検索も同じ構文
```

## 2 回目からの検索を速くする

ブラウザは初めて検索したときに検索用のファイル（辞書・索引・分かち書きのモデル）を
ダウンロードし、対応するブラウザでは**ブラウザ内の保存領域**（OPFS）へ保存します。
次に開いたときは、サイトが更新されていなければ保存したものを使い、ダウンロードし
直しません。保存領域を使えない環境（https でも localhost でもない場合など）では、
毎回ダウンロードします。

> [!NOTE]
> 検索の動作確認は `yuzu preview` / `yuzu dev` で開いて行ってください。
> ファイルとして（`file://` で）開くと検索用のファイルを読み込めません
> （[dist はサーバで配信する](install.md#dist-はサーバで配信する)）。
> 検索が要らなければ、`[search]` に `enabled = false` と書くと機能ごと無効化できます。
